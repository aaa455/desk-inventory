# 开发计划与验收对应

## 开发约定

每次只完成一个步骤，验证后提交并推送到 `aaa455/desk-inventory`，随后停止，说明改动、知识点与浅显理解。下一步收到继续指示后再进行。中文编写手工注释、说明和提交信息；代码标识符、协议字段与工具自动生成内容遵循技术规范。

模型依赖、权重、缓存和输出优先放在项目目录。下载前检查已有环境是否可复用。真实密钥、私人照片和模型大文件不提交。

## 六个步骤

| 步骤 | 交付内容 | 检查方式 | 学习要点 |
| --- | --- | --- | --- |
| 1：基础结构 | 后端入口、健康检查、配置、环境记录和依赖 | 实际启动服务，检查健康响应、接口文档、配置读取 | HTTP 接口、虚拟环境、模块组织、配置与版本管理 |
| 2：图片与检测 | 图片校验、读取、YOLO 类别、置信度、边界框和计数 | 真实桌面样本推理，检查空结果、非法图片和坐标 | OpenCV 图像处理、目标检测、阈值与坐标变换 |
| 3：分割与清单 | 实例掩膜、叠加图、实例明细及分类汇总 | 检查掩膜与原图对齐、重复实例、遮挡及漏检 | 实例分割、点或框提示、掩膜、计数 |
| 4：视觉大模型 | 图像与中文提示、结构化结果、超时和错误处理 | 真实接口调用；校验返回结构与失败提示 | 多模态输入、提示词、API 和结构化输出 |
| 5：终端对比 | PowerShell 同图双方案、类别差异、耗时、图像及清单导出 | 相同字节与摘要、部分失败保留、人工清点与离线评估 | 命令行交互、异步编排、结果归一化、计数评估 |
| 6：验收材料 | 中文项目说明、个人感悟、运行视频与复现流程 | 按运行说明完成演示，核对持续提交历史 | 可复现性、实验分析、项目表达 |

## 传统视觉的选择依据

先采用 YOLO 小模型跑通检测基线，记录支持类别、置信度和边界框。第三步根据显存、Windows 兼容性与样本效果选择 YOLO 实例分割或检测框驱动的 SAM 2 分割；若检测类别无法满足选定桌面样本，再评估 Grounding DINO 等开放词汇模型。模型变化单独记录原因与影响，不直接复制参考仓库脚本。

分割不是分类器；清点的类别和实例数主要取决于检测输出。对漏检和不支持的类别如实展示，不能用手工预设清单冒充推理结果。点、框提示式分割的学习和演示安排在第三步核对。

## 对比规则

两种方案使用同一份原始图片、相同清点范围；分别记录各自缩放方式、模型版本、参数、输入提示与耗时。比较类别、数量、漏检和误检，同时报告服务调用与本地计算的成本差异。没有人工真值时只能称为方案间差异，不能称为准确率。大模型自报的把握程度不能直接等同于 YOLO 的检测置信度。

计划选取整齐桌面、杂乱或遮挡桌面、小物体与相似物体等样本。记录人工清点规则，对看不清的实例保留不确定说明。公开演示材料使用用户允许公开的图片。

## 考核覆盖

交付同一视觉问题的传统模型方案和视觉大模型方案、相同输入的并排对比、适用场景分析、真实持续提交历史、依赖说明、项目和个人感悟文档，以及项目运行视频。学习记录结合模型解释 token、embedding、attention、位置编码、编码器与解码器、多模态输入，以及读取、裁剪、缩放和可视化等图像处理知识。

个人感悟在最后根据实际开发和用户体验整理，不提前编造。

## 第三步模型决定

实际采用 YOLO11n 检测与 SAM 2.1 tiny 框提示分割，直接复用已安装 Ultralytics 8.3.228 和 PyTorch 2.7.1+cu128，仅增加约 78 MB 权重。另提供同一物体的前景／背景点提示与框提示接口，便于理解提示对分割范围的影响。掩膜与检测框按提示索引关联，不按过滤后位置盲目配对。

物品清单默认按类别排除人和大型家具，原检测接口保持整图输出。该规则不能判断真正的桌面范围，第四步视觉模型也应获得相同的清点口径；第五步并排对比须展示漏检与支持类别的限制。

## 第四步接入决定

通过现有 httpx 调用 OpenAI 兼容的 Chat Completions 图像接口，不增加 SDK。当前用户指定的第三方服务与 gpt-6.1-sol 已完成真实验证。默认 JSON 模式，支持显式切换严格 Schema 或普通文本；不因错误自动降级、重试或更换模型。

两条流程共享图片预处理与背景类别配置，模型只接收图片与中文规则，不接收传统方案结果。清单结构严格校验，总数由后端汇总；固定提示、发送图片摘要、模型标识、输出配置及服务自报令牌用量留在结构化结果中。第五步在此基础上开发同图并排比较与人工核对。

## 第五步交互决定

按用户明确选择改为 PowerShell 命令行，不交付网页，也不要求运行 HTTP 服务。中文脚本直接调用项目 Python 和共享分析服务；原有 HTTP 接口保留。一次分析两份独立结果，终端并列计数，图像与掩膜导出文件。

人工模板初始数量为空，需查看原图填写并明确确认；可以补充双方案都漏掉的类别。离线核对读取已保存结果与对应图片摘要，不再调用任何模型。暂以单张公开样本验证流程，不把该例推广为整体准确率。
