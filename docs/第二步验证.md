# 第二步：图片输入与 YOLO 检测

验证日期：2026 年 10 月 18 日。

## 已实现

`POST /api/detect` 接收图片，通过内容识别格式，不依赖文件扩展名。支持 JPEG、PNG 和 WebP 静态图片，限制文件字节数和像素数，拒绝空文件、损坏内容、动画和不支持格式。校正 EXIF 方向，透明区域使用白色背景，转成 OpenCV 的 BGR 数据；长边默认限制为 1600，YOLO 内部保持比例缩放补边到模型输入。

推理使用本地 YOLO11n 权重，懒加载并复用模型对象。`auto` 设备在 CUDA 可用时选择 GPU，否则使用 CPU；显式指定设备失败时返回错误，不隐藏失败切换设备。接口缺少模型时返回 503，不在 HTTP 请求中静默下载。

返回中文类别、模型原始类别、置信度、原图边界框、分类计数、图像摘要、处理尺寸、耗时和标注图。模型推理使用互斥锁；图片处理在线程池中执行，避免直接阻塞异步接口循环。

- 空白图与大图由本地测试生成：空白图为 640×480 白色图片，大图是公开咖啡图放大至 2400×1600，仅用于检查缩放链路，不是新的独立识别样本。

## 真实运行结果

通过真实本地 HTTP 服务上传公开照片，并实际调用 GPU 检测，得到以下结果：

| 类别 | 数量 | 置信度 |
| --- | --- | --- |
| 杯子 | 1 | 0.8181 |
| 餐桌 | 1 | 0.7842 |
| 勺子 | 1 | 0.2854 |

检测阈值 0.25，重叠去重阈值 0.45。首次请求总耗时约 1869.66 ms，推理调用约 483.28 ms，包含模型初始化或预热影响。另用 CPU 实际推理得到相同类别与数量，单次调用约 75.31 ms；两次调用条件不同，不能由此判断 CPU 比 GPU 更快。

大图预处理至 1600×1067，类别数量一致，返回坐标在 2400×1600 原图范围内。白色空白图返回 `total=0`、空列表与空计数。实际运行 `scripts/detect_image.py`，已生成本地 `outputs/detection.json` 与 `outputs/detection.jpg`，并检查标注框与编号；真实接口验证记录在本地 `outputs/step2-verification.json`。健康检查与交互接口文档均正常响应，验证结束后服务已停止。

## 已知限制与下一步

当前仅用一个真实场景样本验证链路，不构成准确率评估。杯子框包含部分周围区域，勺子置信度偏低；图中的碟子未作为独立实例检出。类别只覆盖预训练 COCO 的 80 类，纸笔、橡皮等常见桌面物品尚不能可靠识别。

当前 `total` 包含餐桌本身；它表示整图检出实例数，不表示用户心目中的桌面小物件数。对比界面阶段应先统一两种方案的清点范围，再做公平计数比较。下一步实现实例分割与清单整理，依据效果决定采用何种分割模型；本步没有用规则伪造分割或识别结果。
