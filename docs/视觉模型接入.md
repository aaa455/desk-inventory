# 视觉模型接入与学习记录

## 本步的数据链路

本地照片 → 统一校验与方向校正 → 按最长边缩放 → 编码 PNG → 中文提示与图片共同发给模型 → 校验 JSON → 后端排除背景类别、计算清单总数。

大模型流程不调用检测或分割服务。传统流程与大模型流程都复用图片预处理函数，返回原始上传文件的 SHA256，用来证明输入来自同一份文件。大模型额外记录发送的 PNG 摘要；同一原图重新编码后，文件摘要可以不同，不能只比较两种文件的字节。服务端缩放到相同尺寸，不代表上游模型内部不再缩放。

相同清点口径是“整张照片中可见的独立物体，默认排除人和指定家具”。两条流程目前都不判断空间上的桌面范围。可识别类别不同会导致清单差异，第五步才做界面与样本评估。

## 配置与协议

采用 OpenAI 兼容的 Chat Completions 协议，向基础地址追加 /chat/completions。鉴权头为 Bearer 密钥；密钥只从后端配置读取，不由上传表单传入。模型名保留用户配置，项目不擅自换成其他模型。

请求有两条消息：系统消息给出中文规则；用户消息包含固定文字和 image_url 图像部分。图片使用 data:image/png;base64,... 发送，detail 固定为 high，不建立公开图片链接。

可选输出模式：

| 配置 | 发送方式 | 用途与边界 |
| --- | --- | --- |
| json_object | response_format.type 为 json_object | 当前第三方服务已验证可用；有效 JSON 不等于字段和含义正确 |
| json_schema | 携带严格 JSON Schema | 服务和模型明确支持时使用；仍执行本地校验 |
| text | 不携带 response_format | 兼容仅支持普通文字输出的视觉服务；完全依靠提示约束，允许外包一层标准 JSON 代码块 |

服务拒绝参数时不自动降级或重试，避免同一次分析暗中更换条件、重复费用。按服务文档手动修改模式后重启后端。输出令牌字段默认 max_completion_tokens；仅接受 max_tokens 的兼容服务可通过配置切换。

本机验证配置为用户提供的 https://api.hangzhale.com/v1 与 gpt-6.1-sol。该服务返回相同模型名，但模型标识与令牌用量均为服务自报，本项目无法核实其底层实现或收费规则。

官方格式参考于 2026 年 10 月 18 日读取的 [OpenAI 图像输入指南](https://developers.openai.com/api/docs/guides/images-vision) 和 [结构化输出指南](https://developers.openai.com/api/docs/guides/structured-outputs)。第三方服务的具体能力仍以实际调用和其文档为准，不据此假定完全兼容。

## 清单约束

模型只生成 items 和 uncertainties，每个类别包含中文名、英文名、正整数数量及不确定说明。同一中文或英文类别名重复时拒绝本次结果，不直接相加，以免把同一批物体算两遍。不接受小数、字符串或布尔值充当数量，也不接受模型额外提供的 total。

类别英文名统一小写与空格；只做确定的格式归一化，不模糊合并 coffee cup 与 cup 等同义词。默认背景类别仍来自统一的 INVENTORY_EXCLUDED_LABELS 配置。模型若误用类别名，可能绕过类别排除，这是语义局限，需人工核对。

后端根据纳入清单的类别明细计算 counts 和 total，将排除项、原因和不确定说明单独返回。没有物体时应是合法空数组；解析失败绝不伪装成“没有物体”。本流程不生成分割掩膜或可靠位置框，不提供可与 YOLO 比较的置信度。

## 超时与错误处理

远程调用采用异步 HTTP，不占用本地模型推理锁。单次调用具有整个请求的总时限，默认 120 秒；上游正文最多读取 1 MiB，不跟随重定向，不自动重试。

| 后端状态 | 含义 |
| --- | --- |
| 400 / 413 / 422 | 无效图片、上传过大、缺少文件或模型明确拒绝分析 |
| 503 | 配置不全或本地处理暂时失败 |
| 502 | 上游鉴权、网络、参数、响应格式、截断或其他服务错误 |
| 429 | 上游限流或额度不足 |
| 504 | 调用超时 |

接口只返回经过整理的中文提示，不透传上游错误正文、密钥或图片编码。日志中的未预期异常仅记录类型。图像会发送到已配置服务；本地后端不持久化原图或原始上游响应，命令行工具保存结构化清单。密钥应只填写 .env，不要填写 .env.example。

## 浅显理解与相关知识

可以把视觉模型看成另一位清点员：他拿到相同照片和清点规则，独立填写表格。后端像表格审核员，检查栏位和数量格式，再算总数。审核员能发现“数量写成半个”等格式问题，不能保证清点员没把碟子漏看。

- 多模态输入：把文字规则和图像一起提供给模型；图片不是先由 YOLO 变成文字再交给模型。
- 提示词：明确什么算一个物体、如何处理遮挡、输出哪些字段。它能减少歧义，不能保证模型始终遵守。
- Token：模型处理信息的计量单位。中文字符、英文单词与 token 不是一一对应，图片也可能转换为视觉 token。返回的使用量并不直接等于费用。
- Embedding：把文字或图像区域转换为模型可运算的向量，好比将不同输入译成内部通用的数字表达。
- Attention：根据当前处理内容，综合图片区域和文字之间的关系；清点勺子时可以结合杯沿、反光等线索。
- 位置编码：帮助模型保留顺序或空间位置的线索，避免只知道有哪些图像碎片却丢掉布局。
- 编码与解码：可把图像理解过程类比为“把画面整理成内部表示”，把生成 JSON 类比为“逐步写出回答”。这是概念解释，不能据此推断第三方模型的真实架构。
- 异步调用：等待网络响应时允许服务处理其他工作；它不意味着无限并发或高并发能力已经验证。
